현재 시스템 한계
📦
저장 용량 상한 5 MB
건물 사진을 base64로 저장하면 2~3장만으로 상한에 도달합니다. 15개 건물에 각 1장씩 등록하면 저장 불가 오류가 발생합니다.
👤
단일 사용자 구조 — 협업 불가
데이터는 각자의 브라우저에만 존재합니다. A가 수정한 내용을 B가 볼 수 없으며, JSON 파일을 이메일로 주고받는 방식으로 동기화해야 합니다.
📷
이력 없는 스냅샷 구조
현재 비품·건물 데이터는 "현재 값"만 저장합니다. 지난달에 얼마였는지, 누가 언제 변경했는지 추적할 수 없습니다. 월별실적도 사람이 수동으로 채워야 의미가 생깁니다.
📃
임대차·유지보수 데이터 부재
건물의 임차인이 단일 문자열 하나입니다. 계약 기간·월세·만료일·갱신 여부를 관리할 수 없고, 유지보수 비용 데이터도 없어 건물 원가 분석이 불가능합니다.
📤
보고서 자동화 불가
월말 보고서를 만들려면 현재 수치를 수동으로 취합해야 합니다. DB가 없으면 스케줄러가 읽을 데이터 소스 자체가 존재하지 않습니다.

신규·강화 화면 상세
① 자산 현황 강화
현재 히어로 KPI + 드릴다운 구조 유지. DB 연동으로 자동 시계열과 공간 정보가 추가됩니다.
YoY·QoQ 비교 차트 — asset_snapshots 자동 집계
지역 지도 핀 — 건물 위치 + 자산가치 버블
ROI 계산 — 취득가 대비 임대수익 연환산
감가상각 진행률 바 — 잔존가치 자동 계산
필요 테이블: asset_snapshots, buildings, lease_contracts, depreciation_schedules
② 임대차 관리 신규 — 우선순위 최상
현재 임차인 정보가 단일 문자열입니다. 계약 단위로 관리하면 재무팀이 별도 Excel 없이 이 탭만으로 임대 현황을 완결할 수 있습니다.
계약 Gantt 타임라인 — 만료 30·60·90일 컬러 구분
임박 만료 경보 카드 — 자동 산출
월세 수납 현황 — 예정 vs 실수납 비교
임차인 포트폴리오 — 업종 분포 도넛 차트
계약 추가·편집 모달 — DB CRUD
공실률 자동 재계산 — 건물 카드 연동
필요 테이블: lease_contracts (신규), buildings
③ 유지보수 이력 신규
현재 건물 유지보수 지출 데이터가 전혀 없습니다. 이 탭이 생기면 건물별 실질 원가 분석이 처음으로 가능해집니다. 데이터가 쌓일수록 가치가 올라갑니다.
건물별 유지보수 비용 — 연도별 히스토그램
카테고리별 비용 분포 — 전기·소방·구조·수선·청소
작업 상태 칸반 — 예정→진행→완료
업체별 발주 현황 및 예산 소진률
필요 테이블: maintenance_logs (신규), buildings
④ 비품 원장 강화
현재는 월별 스냅샷 구조로 "지금 값"만 있습니다. 거래 원장으로 전환하면 품목별 전체 이력 조회와 감가상각 자동 계산이 가능합니다.
품목별 거래 히스토리 — 일자·수량·담당자
내용년수 대비 노후화 리스트 — 교체 우선순위
카테고리 트리맵 — IT·소방·물류·가전 구성비
이동 경로 추적 — 본사→매장 경로별 흐름
필요 테이블: equipment_items, equipment_ledger (원장 전환), depreciation_schedules
⑤ 보고서 / 알림 신규
월말 자산 현황 보고서를 자동으로 생성하고 담당자에게 발송합니다. 계약 만료 경보도 이 채널을 통해 전송됩니다.
월간 자산 보고서 PDF 자동 생성
임대차 만료 예보 리스트 이메일 발송
분기별 감가상각 명세 자동 산출
건물별 종합 현황 1-pager 다운로드
필요: 모든 테이블 + Supabase Edge Function + SMTP

DB 스키마 설계

현재 2개 객체(비품·건물)에서 7개 테이블로 확장됩니다. 기존 데이터는 자동 마이그레이션 스크립트로 이전합니다.

테이블 상태 주요 신규 필드 연결
buildings 확장 building_type · insurance_expiry · last_inspection_date · photo_url · updated_by → lease_contracts, maintenance_logs
equipment_items 확장 category · unit_price · lifespan_years · is_active → equipment_ledger
equipment_ledger 신규 transaction_type (purchase/transfer/disposal) · location_type · amount · quantity · recorded_at · recorded_by ← equipment_items
lease_contracts 신규 tenant · floor_unit · monthly_rent · deposit · contract_start/end · auto_renew · status ← buildings
maintenance_logs 신규 category (전기/소방/구조/수선) · work_date · cost · vendor · status · description ← buildings
asset_snapshots 신규 snapshot_date · total_asset · tangible · intangible · equipment · location_hq/store/logistics 월말 자동 적재
depreciation_schedules 신규 asset_type · acquisition_price · lifespan_years · method · book_value · fully_depreciated_at ← buildings, equipment_items

Phase A 선행 이유

Phase A는 화면을 전혀 바꾸지 않고 데이터 저장소만 교체합니다. 이 단계가 완료되면 B·C·D·E 모두 신규 탭을 얹는 방식이 되어 기존 코드를 건드릴 필요가 없습니다. 순서를 바꾸면 이후 단계에서 데이터 이중화 문제가 발생합니다.

Phase B 우선순위 최상인 이유

임대차 계약은 현재 단일 문자열로 관리되고 있어 만료 일자 추적이 불가합니다. lease_contracts 테이블 하나로 재무팀이 즉시 활용 가능한 완결된 화면이 만들어집니다. 신규 탭 하나를 추가하는 것으로 완결되므로 리스크도 낮습니다.

단계별 요약
단계 핵심 작업 신규 화면 신규 테이블 공수 임팩트
Phase A localStorage → Supabase 교체 없음 (기능만 강화) buildings, equipment_items, asset_snapshots 1~2주 다중사용자·용량한계 해소
Phase B 임대차 탭 신설 임대차 관리 lease_contracts 2~3주 재무팀 직접 활용 가능
Phase C 유지보수 탭 신설 유지보수 이력 maintenance_logs 2주 건물 원가 분석 최초 가능
Phase D 비품 원장 전환 비품 원장 (강화) equipment_ledger, depreciation_schedules 3~4주 회계·감사 대응
Phase E 보고서 자동화 보고서·알림 audit_logs 4주+ 경영진 직보 채널
