2
현재 시스템 한계 분석

5가지 구조적 한계가 확장을 막고 있습니다. 모두 DB 도입으로 해소됩니다.

📦
저장 용량 5MB 천장
건물 사진 base64 저장 시 3~4장만으로 상한 도달. 15개 건물 사진 관리 실질 불가. Supabase Storage(S3 호환) 전환으로 용량 제한 없음.
👥
단일 사용자 — 협업 불가
데이터가 각자 브라우저에만 존재. A가 수정해도 B는 볼 수 없음. JSON 파일 이메일 공유가 유일한 동기화 방법. Supabase Realtime 연동 시 즉시 해소.
📷
스냅샷 구조 — 이력 없음
비품·건물 데이터는 현재값만 저장. 누가, 언제, 무엇을 변경했는지 추적 불가. 원장(ledger) 구조 전환과 audit_logs 트리거로 해소.
📋
임대차·유지보수 데이터 부재
임차인이 단일 문자열 1개. 계약 기간·만료일·월세를 관리할 구조 없음. 유지보수 비용 데이터도 전혀 없어 건물 실질 원가 계산 불가.
📊
보고서 자동화 불가
월말 보고서를 매달 수작업으로 취합. 스케줄러가 읽을 데이터 소스 자체가 없음. Edge Function + asset_snapshots 도입으로 자동화 가능.

4
신규·강화 화면 상세

Stage 2에서 추가되는 탭과 Stage 3에서 강화되는 화면입니다.

자산 현황 강화
현재 히어로·드릴다운 구조 유지. DB 연동으로 자동 시계열과 공간 정보가 추가됩니다.
Stage 1부터
YoY · QoQ 비교 차트 — asset_snapshots 시계열 자동 집계
건물 위치 지도 핀 — 자산가치 버블 (Kakao Maps, Stage 3)
ROI 계산 — 취득가 대비 임대수익 연환산
감가상각 진행률 바 — 잔존가치 자동 계산
필요 테이블: asset_snapshots · buildings · lease_contracts · depreciation_schedules
임대차 관리 신규
현재 임차인이 단일 문자열. 계약 단위 관리로 전환하면 재무팀이 이 탭만으로 임대 현황을 완결합니다.
Phase B · 우선순위 최상
계약 Gantt 타임라인 — 만료 30·60·90일 컬러 구분
임박 만료 경보 카드 — 자동 산출
월세 수납 현황 — 예정 vs 실수납 비교
임차인 포트폴리오 — 업종 분포 도넛 차트
계약 추가·편집·종료 모달 — DB CRUD
공실률 자동 재계산 — 건물 카드 연동
필요 테이블: lease_contracts (신규) · buildings
유지보수 이력 신규
현재 유지보수 지출 데이터 없음. 이 탭이 생기면 건물별 실질 원가 분석이 처음으로 가능해집니다.
Phase C
건물별 유지보수 비용 — 연도별 히스토그램
카테고리별 비용 — 전기·소방·구조·수선·청소
작업 상태 칸반 — 예정 → 진행 → 완료
업체별 발주 현황 및 예산 소진률 게이지
필요 테이블: maintenance_logs (신규) · buildings
비품 원장 강화
현재 월별 스냅샷 6항목 → 거래 원장 구조 전환. 품목별 전체 이력과 감가상각이 자동화됩니다.
Phase D
품목별 거래 히스토리 — 일자·수량·담당자
내용년수 대비 노후화 리스트 — 교체 우선순위
카테고리 트리맵 — IT·소방·물류·가전 구성비
이동 경로 추적 — 본사→매장 경로별 흐름
필요 테이블: equipment_items · equipment_ledger (원장 전환) · depreciation_schedules
보고서 자동화 신규
월말 자산 보고서 자동 생성 및 담당자 이메일 발송. 감사인 전용 접근 계정도 부여 가능합니다.
Phase E
월간 자산 보고서 PDF 자동 생성
임대차 만료 예보 리스트 이메일 발송
분기별 감가상각 명세 자동 산출
건물별 종합 현황 1-pager 다운로드
필요: 모든 테이블 + Supabase Edge Function (Deno) + SMTP

RBAC 권한 설계

4가지 역할. Supabase Row Level Security(RLS)로 DB 레벨에서 강제됩니다. 프론트엔드 접근제어만으로는 불충분하며 RLS가 필수입니다.

RLS 정책 구현 예시
buildings 테이블 RLS
-- 읽기: 전체 역할
CREATE POLICY "buildings_select" ON buildings
  FOR SELECT USING (auth.role() IN ('admin','editor','viewer','auditor'));

-- 쓰기: editor 이상
CREATE POLICY "buildings_write" ON buildings
  FOR INSERT OR UPDATE USING (auth.role() IN ('admin','editor'));

-- 삭제: admin only
CREATE POLICY "buildings_delete" ON buildings
  FOR DELETE USING (auth.role() = 'admin');

비품 재고 계산 (RPC)
-- PostgreSQL 함수 (서버사이드)
CREATE OR REPLACE FUNCTION get_equipment_inventory(as_of DATE)
RETURNS TABLE(equipment_id UUID, location_type TEXT, balance BIGINT) AS $$
  SELECT equipment_id, location_type,
    SUM(CASE WHEN transaction_type = 'purchase' THEN amount
         WHEN transaction_type = 'disposal' THEN -amount ELSE 0 END) AS balance
  FROM equipment_ledger
  WHERE recorded_date <= as_of
  GROUP BY equipment_id, location_type;
$$ LANGUAGE sql;
